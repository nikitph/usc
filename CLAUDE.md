# CLAUDE.md — Agent Constitution for the Universal Systems Compiler (USC)

You are implementing the Universal Systems Compiler. This file is your binding contract.
It is inherited by every task in this repo. If anything you are asked to do conflicts with
this file, STOP and flag the conflict instead of resolving it yourself.

## 0. The Hierarchy of Authority

1. `fixtures/` — adjudicated ground truth. You NEVER modify these (see §4).
2. `schemas/` — single source of truth for all data shapes. Generated code only.
3. `specs/<subsystem>/SPEC.md` — your working contract for the current packet.
4. `docs/STANDARDS.md` — code-quality rules (project-adapted; the deviations table there
   overrides the generic standards where they conflict).
5. `docs/BLUEPRINT.md` — canonical design. Read sections referenced by your packet; do not
   re-architect from it.

A work packet (`packets/`) tells you exactly which spec sections and fixtures apply.
**Never work outside an assigned packet's scope.** If the packet seems to require touching
another subsystem, stop and flag.

## 1. System Invariants (you will be mechanically checked against these)

- **INV-1 (Unknown):** `unknown` is NEVER coerced to `valid`/success. Kleene three-valued
  logic only, via `evaluateAnd/evaluateOr/evaluateNot` from `packages/kernel`. Never write
  ad-hoc boolean logic over `Verdict3.value`. Property tests will catch you.
- **INV-2 (Determinism):** `packages/kernel` is pure. No I/O, no `Date.now()`, no
  `Math.random()`, no LLM calls, no imports from `store`/`runtime`/frameworks. Same
  rulebase + same AST = same verdicts, byte-identical.
- **INV-3 (Immutability):** Artifacts are append-only. No `UPDATE` on `artifacts` rows
  except lifecycle/tag metadata columns explicitly listed in `specs/store/SPEC.md`.
  Revision = new artifact with parent links.
- **INV-4 (Provenance):** Every artifact records `rulebase_hash`, `parents`, and (if
  LLM-derived) `extractor_version`. An artifact without provenance is a schema error.
- **INV-5 (Span grounding):** Every motif token carries a source span. Tokens without
  spans fail schema validation — do not relax the schema to make data fit.
- **INV-6 (Two-mode):** Production-decision artifacts (gate verdicts, recommendations, KG
  insertions, transfer-score updates) must fail validation if their derivation DAG
  contains an `experimental`-tagged extraction. This check lives in the kernel provenance
  query; never bypass it with a code path.
- **INV-7 (Fail to pending):** The action gate's verdict on any budget exhaustion, timeout,
  or internal error is `pending` with named evidence gaps. NEVER `allow`. NEVER a silent
  retry that masks the gap.
- **INV-8 (No swallowed errors):** Every catch either recovers meaningfully, translates to
  a typed domain error and re-throws, or logs-and-re-throws. Returning a default value on
  failure is converting an outage into a wrong answer — forbidden.
- **INV-9 (Schema SoT):** Data shapes are defined ONCE in `schemas/*.schema.json`. Zod and
  Pydantic are generated by `make codegen`. Hand-editing generated files in
  `packages/shared/src/generated/` or `workers/offline/generated/` fails CI.

## 2. Workflow (every packet, in order)

1. Read the packet file fully. Read the spec sections and fixtures it lists. Nothing else.
2. State your plan in ≤10 lines as a comment in the PR/commit description BEFORE coding.
3. Implement. Small commits, conventional messages (`feat:`, `fix:`, `refactor:`).
4. Run `make verify` locally. The packet is done ONLY when verify is green AND the
   packet's listed fixtures pass. *Bootstrap exception (owner-adjudicated 2026-06-12,
   see packets/mvp0/K-03-BLOCKED.md): until packet K-06 lands the fixture runner,
   "verify green" means the packet's stated Exit criteria plus every verify target
   already implemented (typecheck, schemas, properties, lint, protected). Never
   stub a verify target to make it pass.*
5. Self-review against §1 invariants and the STANDARDS.md checklist. List in the commit
   description any invariant you came close to violating and how you avoided it.
6. If you could not satisfy a fixture without changing it: STOP. Write a
   `packets/<id>/BLOCKED.md` explaining why the fixture seems wrong. A human adjudicates.

## 3. Definition of Done

`make verify` green = typecheck (TS strict, mypy strict) + schema validation of all
fixtures + fixture regression runner + kernel property tests + lint + protected-path
check. There is NO unit-test-count requirement. Do not write speculative unit tests to
look thorough; the contract is the fixtures. You MAY add a unit test when it pins a bug
you actually hit — name it `should_<outcome>_when_<condition>`.

## 4. Protected Paths — never modify without an explicit human-approved packet

- `fixtures/**` (ground truth; agents may DRAFT new fixtures into `fixtures/_proposed/`
  for human adjudication, never into the live tree)
- `schemas/**`
- `packages/kernel/rulebase/**` (the Atlas rules are data; rule changes are kernel
  versioning events with migration analysis, not edits)
- `CLAUDE.md`, `docs/STANDARDS.md`, `Makefile`, `scripts/verify.sh`, `.github/**`

CI enforces this list via `scripts/check-protected-paths.sh` against the packet manifest.

## 5. Code Rules (condensed; full text + deviations in docs/STANDARDS.md)

- TypeScript strict, `noUncheckedIndexedAccess`, zero `any`/`as any`/`@ts-ignore`
  (`@ts-expect-error` with a reason comment is the only escape hatch). Python: mypy
  strict, no `type: ignore` without reason.
- Immutable by default: `readonly` fields, `Readonly<T>` returns, frozen objects in
  kernel. Python: frozen dataclasses / Pydantic `model_config = {"frozen": True}`.
- Absence is explicit: no `null` for domain meaning; use discriminated unions
  (`{kind:"unknown", gaps:[...]}`), never sentinel values.
- Branded types at boundaries: `ArtifactId`, `MotifId`, `RulebaseHash`, `CaseId` are
  branded strings validated at construction. Inside a module, plain locals are fine —
  do NOT wrap every intermediate value (see STANDARDS.md deviation D2).
- Typed errors per failure domain: `SchemaValidationError`, `ProvenanceError`,
  `BudgetExhaustedError`, `RulebaseConflictError`. Never `throw new Error("oops")`.
- Variation points use registries only where the spec marks them `[VARIATION-POINT]`
  (emitters, extractors, evidence fetchers, dedup hashers). Everywhere else, a plain
  function and a readable `switch` over a closed union is correct — do not pattern-ify.
- Naming: domain words, greppable, booleans as questions. No `data`, `result`, `item`,
  `temp`, `handler` as standalone names.
- Functions: aim ≤50 lines; exceeding it is allowed ONLY with a one-line comment stating
  why splitting would hurt cohesion (this is a guideline, not a gate).
- DB: all schema changes via migrations in `packages/store/migrations/` (up + down),
  FKs/checks/not-nulls in the database, parameterized queries always, audit columns +
  soft deletes per store SPEC.
- Structured logs (JSON) with `correlationId` at every service boundary; the gate API
  logs every verdict with its `Verdict3` provenance.
- Config from env with safe local defaults; no secrets anywhere in the repo, including
  test files and comments.
- One concept per file; feature/subsystem-based organization (already laid out — keep it).

## 6. LLM-Calling Code (workers and runtime extraction paths)

- Every LLM call site declares: model tier (0–4 per blueprint §"cost tiers"), max tokens,
  timeout, and what happens on failure (always degrade to `unknown`/`candidate`, never
  fabricate).
- Raw LLM output is stored as an artifact BEFORE parsing. Parsing failures are data
  (`extraction_failure` artifact), not exceptions to swallow.
- Extraction outputs validate against `schemas/motif_token.schema.json` — reject, don't
  repair silently. Repair attempts are a second, logged call.

## 7. Things You Must Never Do

- Coerce `unknown` to anything. (INV-1)
- Edit a fixture, schema, or rulebase file to make your code pass. (§4)
- Add a dependency without listing it + reason in the commit description.
- Implement features not in the current packet ("while I was here…").
- Write to the database except through `packages/store` repositories.
- Catch-and-continue. (INV-8)
- Mark a packet done with a red `make verify`.
